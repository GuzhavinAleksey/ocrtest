# PDF → PNG → показатели бухгалтерской отчётности

Требуется Node.js >= 22.13 (проверено на 24.19), `npm ci` и OpenAI-совместимый vLLM с моделью, принимающей изображения.

```bash
npm ci
npm run qwen -- report.pdf output --convert-only
```

Сначала читается текстовый слой всех страниц. В PNG конвертируются только страницы таблиц форм ОКУД **0710001, 0710002, 0710004, 0710005**, включая продолжения. В приложенном `report.pdf` это страницы PDF **11–19** (нумерация с 1). Другие страницы не рендерятся и не отправляются модели. PDF без текстового слоя требуют предварительного OCR; автоматического определения форм на сканах нет.

Для полного извлечения задайте переменные в окружении (ключ не сохраняйте в Git):

- `OPENAI_API_URL` — адрес вашего доступного vLLM с `/v1`;
- `OPENAI_API_MODEL` — точное имя vision-модели на сервере;
- `OPENAI_API_KEY` — ключ, если сервер требует авторизацию. Для vLLM без авторизации можно оставить пустым.

```bash
npm run qwen -- report.pdf output
```

Результат: PNG выбранных страниц и `output/financials.json`. Без API режим `--convert-only` создаёт PNG и `manifest.json`, но не финансовые данные. Полный запуск требует доступности вашего vLLM из среды выполнения. Вывод JSON также идёт в stdout, сообщения о ходе обработки — в stderr.

Структура JSON:

```json
{
  "source": "/path/report.pdf",
  "status": "extracted",
  "pages": [{
    "page": 11,
    "form": "0710001",
    "png": "page-11-0710001.png",
    "indicators": [{
      "code": "1100",
      "name": "Итого по разделу I",
      "values": {"На 31 декабря 2025 г.": 23339986338, "На 31 декабря 2024 г.": 23197589630, "На 31 декабря 2023 г.": 23167100416}
    }]
  }]
}
```

Пример сокращён до одной строки. В `src/qwen.ts` перечислены все коды показателей целевых форм из приложенного отчёта. Модель получает список кодов и должна вернуть все видимые строки страницы, включая детализацию. Каждый показатель содержит все столбцы: годы для баланса, финансовых результатов и денежных потоков; семь компонентов капитала для формы 0710004. Даты и годы строк капитала сохраняются в названии. Значения остаются в единицах исходной таблицы (обычно тыс. руб.; прибыль на акцию — руб.). Скобки означают отрицательное значение, прочерк/нечитаемое значение — `null`, ноль — `0`.

Некорректный JSON, неизвестные/повторные коды, неверные числа и обрезанный ответ модели завершают команду с ненулевым кодом. Значения не извлекаются путём угадывания первых чисел ответа. Итоговый JSON записывается после обработки всех выбранных страниц; используйте отдельную папку для каждого документа/запуска, чтобы не смешивать старые результаты. Смысловая точность и полнота распознавания зависят от vision-модели; структура ответа проверяется, но сравнение каждой ячейки с оригиналом автоматически не выполняется.

Проверки:

```bash
node --test tests/qwen.test.cjs
node_modules/.bin/tsc --noEmit --strict --esModuleInterop --skipLibCheck --target ES2020 --module commonjs --ignoreConfig src/qwen.ts
```

Тесты проверяют выбор страниц и реальный PNG-рендер приложенного PDF, обработку чисел, JSON и запрос модели с подменённым клиентом. Это не проверка реального vLLM. Общая команда `npm run build` пока блокируется отсутствующим модулем `src/ocr_type` в отдельном старом примере `src/ocr.ts`; `npm start` ссылается на отсутствующий `src/index.js`. Для этого сценария используйте `npm run qwen`.
